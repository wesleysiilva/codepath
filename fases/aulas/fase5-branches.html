Branches

A ideia de linhas paralelas de desenvolvimento. git branch, git checkout -b, git merge. Por que a branch main deve sempre ter código funcionando.

⏱ ~15 min
📶 Iniciante
5 de 16 aulas

O conceito essencial

A ideia de linhas paralelas de desenvolvimento. git branch, git checkout -b, git merge. Por que a branch main deve sempre ter código funcionando.

💡
Observe a ideia em contextoUma branch é uma referência móvel para uma linha de commits; use `git switch -c feature/busca` para trabalhar separadamente e depois integre com merge. Manter main testada reduz a chance de que uma tarefa incompleta bloqueie a versão estável.

Como aplicar

Uma branch é uma referência móvel para uma linha de commits; use `git switch -c feature/busca` para trabalhar separadamente e depois integre com merge. Manter main testada reduz a chance de que uma tarefa incompleta bloqueie a versão estável.

Ao analisar um caso, identifique primeiro a entrada e o resultado esperado. Depois verifique as condições e os limites descritos acima; essa sequência ajuda a distinguir a regra do exemplo e a transferi-la para outras situações.

Prática e entregável

Crie branch para uma funcionalidade, faça dois commits, integre à main e mostre o grafo de histórico. Explique o que fazer caso a funcionalidade ainda não esteja pronta para publicação.

🎯
Critério de conclusãoEntregue o artefato solicitado com um exemplo testado, explique a decisão tomada e registre ao menos um limite ou caso de borda.
